| **Q10: How can the scanner distinguish passive documentation examples from active instructions?** | NotebookLM proposed using Markdown AST/heading structure, fenced-code context, imperative-versus-descriptive language, proximity between trigger verbs and commands, optional tool declarations, and file location (`SKILL.md` versus auxiliary files) to add context to detections. A safer first version is to detect the indicator, retain its line/context, and optionally add context tags rather than downgrading or removing it automatically. | **Q11: Can matching `name` + normalized `description` with different `file_sha` values identify likely modified/reused skill families?** | NotebookLM agreed this is a practical high-precision candidate-generation strategy: require the same frontmatter `name` and normalized `description`, require distinct content hashes, then order candidates by `first_commit_at`.
