# Background and related work

The Agent Skills specification describes a reusable instruction file (`SKILL.md`) with optional scripts, references, and other resources [@agentskills]. This format helps explain what a skill may contain, but it does not establish that its instructions are safe or have been executed. GitSkills provides the dataset for our study: it records agent-skill occurrences found in public GitHub repositories, including their locations and content hashes [@gitskills]. Repeated occurrences make it possible to look for related skills, although the dataset does not provide a verified history of copying between them.

Recent security research has examined the risks present *within* agent skills. Liu and colleagues developed SkillScan to analyze vulnerable patterns, including data exposure, privilege escalation, and supply-chain concerns [@skillswild2026]. Another study combined static screening with behavioral verification to investigate malicious skills distributed through community registries [@maliciousskills2026]. These studies help establish why skill contents deserve security review. Our study asks a different question: **what security-sensitive operations appear or change between related skill artifacts?** Their detection rates cannot be compared directly with ours because the datasets, definitions, and validation methods differ.

Research has also begun examining how skills evolve. Huang and colleagues studied changes to skills using GitHub commit histories, including which components are modified and why [@skillevolution2026]. Our data does not contain a complete version history for each skill. We therefore use content similarity and an ordered set of direction clues to construct *plausible* comparisons, without claiming to recover the actual history of reuse.

Our contribution is a reproducible method that brings these concerns together: identify related artifacts, record what supports their ordering, compare their instructions and available supporting files, and assess specific changed operations against defined risk indicators. The goal is to identify changes worth reviewing, not to label entire skills as malicious or demonstrate that an instruction executed.
