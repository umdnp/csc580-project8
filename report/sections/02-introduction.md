# Introduction

AI coding agents can use reusable instructions, known as *agent skills*, to perform specialized work. Under the Agent Skills specification, a skill includes a `SKILL.md` instruction file and may also contain scripts, reference documents, and other supporting resources [@agentskills]. Developers can adopt and adapt these packages instead of writing every workflow from scratch.

That convenience also creates a trust question. *Software supply-chain security* concerns risks introduced through software, code, or other resources obtained from outside a project. An agent skill may instruct an agent to execute a script, install software, contact an external service, or access local files. A copied or modified skill can retain its familiar name and purpose while changing what the agent is asked to do. The change may be legitimate, but it can also introduce an operation the person adopting the skill has not reviewed. As a result, judging a skill only by its name or description can miss a meaningful security-sensitive change.

Studying these changes is not as simple as comparing numbered software releases. Skills are found in different repositories, and files with the same name are not necessarily related. GitSkills is a research dataset of agent-skill files collected from public GitHub repositories [@gitskills]. Its many recorded occurrences make it possible to search for related skills and examine how their instructions and supporting resources differ. However, the dataset does not provide a verified history showing which skill was copied from which, and some historical or supporting-file information is missing.

Our research asks whether modified or reused skills introduce command execution, network access, file-system access, or other security-sensitive behavior absent from a plausibly earlier observed artifact. We investigate this by comparing stored skill content, establishing relationships and direction only where the available evidence supports them, and identifying operational changes that warrant review. We do not execute the skills or attempt to determine malicious intent. The goal is to give developers and security reviewers a reproducible way to focus on what changed and why it may matter.
