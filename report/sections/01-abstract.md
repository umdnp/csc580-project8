# Abstract

Agent skills can instruct AI agents to execute commands, access files, use networks, install code, modify systems, and handle credentials. This study asks whether modified or reused GitSkills artifacts contain security-sensitive instruction patterns that are absent from an earlier or related artifact. We use the GitSkills `agent_skills_release.db` dataset and a rule-based static analyzer that scans text without executing instructions. Candidate artifacts are grouped by exact skill name, compared using token-shingle similarity, and ordered only when provenance, observed chronology, repository boundaries, or asymmetric containment provides direction evidence.

The completed Sprint 1 exploratory workflow analyzed 43 artifacts from 10 skill-name groups. Its view-order adjacent-pair analysis produced 33 scans; 13 pairs (39.4%) had at least one positive rule-count delta, comprising 35 rule-level increases and 77 additional matched instances. These are results from a purposeful development sample, not Sprint 2 population estimates. Sprint 2 has defined a separate 13-case manual-validation sample and protocol, but the reviews and the corresponding generated Sprint 2 results and figures are not yet available. A positive static match-count change is not proof of execution, maliciousness, exploitability, or increased harm. The preliminary evidence supports inspecting changed instructions in context; broader analysis, manual annotation, and robustness checks remain necessary.
